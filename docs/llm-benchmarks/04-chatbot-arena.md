# Chatbot Arena (LMSYS / LMArena)

Chatbot Arena는 고정된 시험지의 정답률보다 실제 사용자가 두 모델의 답변 중 어느 쪽을 선호하는지를 측정하는 공개 비교 플랫폼입니다.
초기 연구는 LMSYS가 발표했고, 현재 Arena 서비스는 익명 대결과 Bradley–Terry 기반 리더보드를 제공합니다.

## 1. 소개

LLM의 답변 품질은 정답 여부만으로 측정하기 어렵습니다.
문체, 설명의 유용성, 지시 준수, 코드 편집 품질, 창의성처럼 사용자가 직접 판단하는 요소가 많기 때문입니다.
Chatbot Arena는 이러한 실사용 선호를 익명 대결로 수집해 공개 순위를 만듭니다.

사용자는 질문을 입력하고, 두 모델의 답변을 본 뒤 더 나은 답변 또는 동점을 선택합니다.
투표 시점에는 모델 이름이 가려져 브랜드 편향을 줄이고, 투표 후 모델 이름을 보여 줍니다.
현재 FAQ는 익명 대결에서 만들어진 표만 공식 공개 리더보드에 반영하고, 이름이 보이는 Side by Side 표는 공식 순위에 반영하지 않는다고 설명합니다.

이 Benchmark의 공신력은 대규모 사용자 표본, 공개된 통계 방법, 실제 업무 질문의 다양성에서 나옵니다.
동시에 표본이 무작위 실험 참가자나 균형 잡힌 국가·언어 표본은 아니므로, 정적 능력 Benchmark와 결합해서 해석해야 합니다.

## 2. 평가 내용

Chatbot Arena는 다음과 같은 능력을 종합적으로 반영합니다.

- 질문 의도 이해와 지시 준수
- 설명의 정확성·완결성·가독성
- 코드·수학·분석·창작 답변의 실용성
- 장문 대화의 일관성
- 답변의 스타일과 사용자 체감 만족도

공개 리더보드는 모델별 rating, 승률, 투표 수와 함께 언어·카테고리·모달리티별 분석을 제공할 수 있습니다.
점수는 객관식 정답률이 아니라 pairwise preference의 통계적 추정치입니다.
따라서 Arena 1위가 모든 과제에서 정답률 1위라는 뜻은 아닙니다.

초기 논문은 240,000표 이상의 데이터를 분석했고, 크라우드소싱 질문이 충분히 다양하고 판별력이 있으며 전문가 평가와도 잘 맞는다고 보고했습니다.
현재 플랫폼의 투표 수와 모델 목록은 계속 변하므로 결과를 인용할 때 스냅샷 날짜를 함께 기록해야 합니다.

## 3. 평가 수행 방법

### 3.1 한 번의 대결

일반적인 Battle mode는 다음 순서로 동작합니다.

1. 사용자가 자유 형식의 프롬프트를 입력합니다.
2. 서버가 비교할 두 모델을 선택합니다.
3. 두 모델에 같은 대화 상태와 프롬프트를 전달합니다.
4. 답변을 A·B와 같은 익명 표기로 사용자에게 보여 줍니다.
5. 사용자가 A 승리, B 승리, 또는 tie를 선택합니다.
6. 투표, 프롬프트, 모델 쌍, 시간, 언어·카테고리 메타데이터를 집계합니다.

### 3.2 Bradley–Terry 집계

현재 공식 FAQ는 투표를 Bradley–Terry 모델로 집계한다고 설명합니다.
모델 `i`의 잠재 점수를 `r_i`라고 하면, 두 모델 비교에서 `i`가 선택될 확률을 다음과 같이 모델링합니다.

```text
P(i가 j보다 선호됨) = sigmoid(r_i - r_j)
```

모든 pairwise 투표를 사용해 `r_i`를 추정하고, 표본 수·승패·tie 처리 규칙에 따라 rating과 승률을 계산합니다.
공식 구현은 스타일 제어와 같은 추가 요인을 통계 모델에 반영할 수 있다고 설명합니다.

### 3.3 자체 모델을 비교할 때

공개 Arena에 직접 의존할 수 없는 조직은 같은 원리를 사내 평가에 적용할 수 있습니다.

1. 제품에서 실제로 나오는 질문을 개인정보 제거 후 수집합니다.
2. 모델 이름을 가리고 동일한 prompt와 컨텍스트를 두 모델에 보냅니다.
3. 평가자가 승자·패자·tie와 평가 이유를 선택하게 합니다.
4. 모델 쌍을 균형 있게 샘플링하고 위치 효과를 교차합니다.
5. Bradley–Terry 또는 paired bootstrap으로 rating과 신뢰구간을 계산합니다.
6. 언어·도메인·난이도·질문 유형별 결과를 분리합니다.

평가자는 “더 그럴듯한 답”이 아니라 정확성, 지시 준수, 근거, 안전성, 유용성의 기준을 먼저 안내받아야 합니다.
전문 사실성이 필요한 영역은 전문가 평가나 객관식 정답 검사를 함께 사용합니다.

## 4. 결과 해석과 한계

Arena 점수는 데이터셋 기반 Benchmark보다 현실적인 사용 감각을 제공하지만, 표본 선택 편향이 큽니다.
사용자가 자주 묻는 질문, 특정 언어권의 사용자, 모델을 선택하는 방법, 서버의 응답 속도가 투표에 영향을 줄 수 있습니다.

모델 버전이 조용히 바뀌거나 시스템 프롬프트·안전 정책이 변경되면 동일한 모델 이름의 rating도 시계열로 비교하기 어렵습니다.
투표 수가 적은 모델의 순위는 불확실성이 크므로 rating 차이만 보지 말고 신뢰구간과 표본 수를 확인합니다.
질문이 공개 데이터로 재사용되면 모델이 Arena의 질문을 학습했을 가능성도 고려해야 합니다.

다음 비교는 서로 대체하지 않습니다.

- Arena: 사용자가 체감한 상대적 선호
- MMLU·GSM8K: 정답이 있는 지식·추론 능력
- HumanEval: 실행 가능한 코드의 기능적 정확성
- TruthfulQA: 잘못된 통념을 피하는 사실성

출시 의사결정에서는 Arena를 최종 사용자 만족의 한 신호로 사용하고, 안전·정확성·비용·지연시간에 대한 통제된 검증을 별도로 통과시킵니다.
