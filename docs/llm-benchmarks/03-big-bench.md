# BIG-bench: Beyond the Imitation Game Benchmark

BIG-bench는 Google을 중심으로 여러 기관의 연구자가 공동으로 만든 대규모 협업 Benchmark입니다.
기존 정적 시험이 포착하지 못한 능력과 모델 규모에 따른 돌파 현상을 탐색하기 위해 서로 다른 형식의 200개 이상 과제를 제공합니다.

## 기본 정보

| 항목 | 내용 |
| --- | --- |
| 정식 명칭 | Beyond the Imitation Game Benchmark |
| 운영 주체 | Google과 132개 기관, 450명 이상 공동 연구자 |
| 대표 논문 | Srivastava et al., TMLR 2023 |
| 규모 | 논문 버전 204개 과제, 현재 저장소는 200개 이상 과제와 24개 BIG-bench Lite 과제 제공 |
| 평가 형식 | JSON 기반 과제와 Python 프로그램 기반 과제 |
| 대표 지표 | exact match, 다중선택, 생성 품질, 과제별 사용자 정의 지표 |
| 자료 | [논문](https://arxiv.org/abs/2206.04615), [공식 저장소](https://github.com/google/BIG-bench) |

## 1. 소개

BIG-bench는 단일 능력이나 고정된 시험지보다 “언어 모델이 앞으로 어떤 능력을 보일 수 있는가”를 폭넓게 탐색하는 협업형 Benchmark입니다.
과제 주제는 언어학, 아동 발달, 수학, 상식, 생물학, 물리학, 사회적 편향, 소프트웨어 개발 등으로 매우 다양합니다.

논문은 모델 크기와 성능 곡선을 함께 관찰해 점진적으로 좋아지는 과제와 특정 규모에서 갑자기 좋아지는 과제를 구분했습니다.
사람 전문가를 같은 과제에 투입해 인간 기준선을 제공한 점도 BIG-bench의 공신력을 높였습니다.

전체 과제는 비용이 크고 과제별 채점기가 다르므로, 실무에서는 24개 과제로 구성된 BIG-bench Lite(BBL)를 먼저 사용합니다.
BBL은 전체 Benchmark의 대표적인 소규모 subset이지, 전체 과제의 완전한 대체물이 아닙니다.

## 2. 평가 내용

BIG-bench 과제는 두 가지 형태로 나뉩니다.

- JSON 과제: 입력과 정답 또는 선택지별 점수를 JSON으로 정의합니다.
- Programmatic 과제: Python 코드에서 여러 차례 모델을 호출하거나 사용자 정의 채점 로직을 실행합니다.

과제는 각자 이름, 설명, 키워드, 최대 입력 길이, 질의 수, 지표, 선호 지표를 갖습니다.
따라서 전체 Benchmark에 단일한 “정답률”이 존재하지 않습니다.
과제에 따라 문자열 완전 일치, 다중선택 확률, BLEU·ROUGE 계열 점수, 구조적 검증, 프로그램 채점기를 사용합니다.

논문이 다룬 대표적인 관심 영역은 다음과 같습니다.

- 다단계 추론과 조합적 사고
- 새로운 규칙과 패턴의 학습
- 상식과 일상 사건 이해
- 언어·문화·사회적 편향
- 과학·수학·프로그래밍 지식
- 모델 규모에 따른 성능 곡선과 calibration

## 3. 평가 수행 방법

### 3.1 과제 선택과 실행

평가 목적에 맞는 과제 목록을 고정하고, 사용한 저장소 커밋과 과제 버전을 기록합니다.
전체 과제를 한 번에 실행하기보다 BBL 또는 제품과 직접 관련된 과제 subset을 정의하는 편이 비용과 해석 측면에서 안전합니다.

공식 저장소는 JSON 과제에 대해 SeqIO를 통한 로딩과 평가 예시를 제공하고, 프로그램 기반 과제에는 `model.generate_text()`와 `model.cond_log_prob()` 인터페이스를 사용합니다.

일반적인 실행 흐름은 다음과 같습니다.

1. 과제의 README와 `task.json` 또는 `task.py`를 확인합니다.
2. 과제의 입력·출력 형식, 정답 후보, 선호 지표를 고정합니다.
3. zero-shot, few-shot, 도구 사용 여부를 과제별로 기록합니다.
4. 모델 응답과 채점기 출력을 함께 저장합니다.
5. 과제별 점수와 인간 기준선을 별도로 보고합니다.
6. 과제 평균을 낼 때 단순 평균인지, 문항 수 가중 평균인지 명시합니다.

### 3.2 JSON 과제의 기본 구조

입력과 단일 정답을 비교하는 과제는 다음과 같은 개념으로 동작합니다.

```json
{
  "input": "1 + 1 = ",
  "target": "2"
}
```

다중선택 과제는 선택지별 목표 점수를 정의하고 모델의 조건부 확률 또는 선택 결과를 비교합니다.
문자열 정규화, 대소문자, 공백, 여러 정답 허용 여부를 과제 README에서 확인합니다.

### 3.3 Programmatic 과제

Programmatic 과제는 여러 라운드의 대화, 상태 추적, 외부 도구 호출, 복합 채점이 필요할 때 사용합니다.
이 경우 과제 코드가 모델 호출 횟수, 최대 입력 길이, 제한 시간, 종료 조건을 결정합니다.
실행자는 네트워크와 파일 접근을 제한하고, 과제 코드와 모델 출력의 로그를 보존해야 합니다.

## 4. 결과 해석과 한계

BIG-bench는 범위가 넓어 모델의 특정 강점과 실패 패턴을 찾는 데 유용합니다.
하지만 과제별 지표와 난이도가 달라 전체 평균을 일반 지능 점수처럼 해석하면 안 됩니다.
같은 모델도 과제 프롬프트와 출력 형식에 따라 성능이 크게 달라집니다.

협업으로 과제가 추가되므로 과제 품질, 데이터 중복, 인간 기준선의 일관성이 모두 동일하지 않습니다.
논문에 수록된 204개와 현재 저장소의 과제 수가 다를 수 있으므로 결과에 Benchmark snapshot을 적습니다.
공식 저장소는 2026년 4월부터 archived 상태로 표시되므로, 사용 중인 평가 도구의 유지보수 상태도 확인합니다.

BIG-bench를 제품 평가에 적용할 때는 다음 원칙을 권장합니다.

- 전체 과제 평균보다 제품 기능과 연결된 과제 묶음을 우선합니다.
- BBL 점수와 개별 과제 점수를 함께 보고 포화된 과제를 식별합니다.
- 모델 크기 비교는 동일한 prompt budget과 sampling 설정에서 수행합니다.
- 정답형 점수와 생성형·프로그램형 점수를 한 축으로 합치지 않습니다.
- 사회적 편향 과제는 해당 문화권과 언어의 맥락을 검토한 뒤 해석합니다.
